# Проверка перед показом клиенту

Есть два варианта запуска:

- **Демонстрация через GitHub Pages:** `node scripts/build-preview.cjs`. Публикуется только содержимое `dist/client-preview/`. Админка и заявки не входят; формы честно показывают демонстрационный режим.
- **Рабочий сайт:** PHP 8.2+ (проверено на 8.4), HTTPS и запись в `data/` и `admin/private/`. Установите PIN: `php scripts/set-admin-pin.php`. Для локальной проверки: `php -S 127.0.0.1:8080 scripts/dev-router.php`.

## Перед публикацией репозитория

**Не публикуйте текущую историю `.git` как публичную без отдельной очистки.** В проекте находились Telegram-токен, стандартный PIN и заявки с контактами. `.gitignore` не удаляет уже существующую историю. Безопасный вариант показа: новый репозиторий только с содержимым `dist/client-preview/`.

1. Отзовите старый Telegram-токен через BotFather и получите новый. Он был встроен в публичный JavaScript. Новый задайте во вкладке Telegram работающей PHP-админки; запросы отправляются только сервером.
2. Задайте новый PIN командой выше. Вход со стандартным PIN отключён.
3. Не загружайте `admin/private/`, `.env`, старые `data/orders.json` и `admin/api/telegram-config.php` в репозиторий.
4. Для Apache включите обработку `.htaccess`. Для Nginx/IIS отдельно запретите HTTP-доступ к `admin/private/`, `scripts/`, `.git/`, `data/.content-*` и служебным PHP-файлам. Предпочтительнее размещать проект на хостинге с корректными правилами доступа.
5. Проверьте резервное копирование данных. Не заменяйте рабочую папку `admin/private/` при обновлении сайта.

## Что исправлено

- Удалены браузерный Telegram-токен и отправка через публичный API Telegram; устранена повторная отправка.
- Убраны ложные сообщения об успешной заявке при отказе сервера. Введён отдельный демонстрационный режим.
- Заявки перенесены из открытого JSON в закрытое хранилище; добавлены блокировка записи, проверка телефона и ограничение частоты запросов.
- Убран локальный обход входа в админку по PIN из JavaScript, отключён стандартный PIN, добавлены срок сессии и ограничение попыток входа.
- Ошибки сохранения статуса больше не изображаются как успешные изменения.
- Сохранение контента проверяет структуру и заменяет файл через временный файл.

## Ограничения проверки

Тесты выполняются на отдельной локальной копии с вымышленными заявками, без отправки Telegram и без изменения рабочих заказов. Реальную доставку Telegram и конфигурацию будущего хостинга необходимо проверить после настройки. GitHub Pages не исполняет PHP: https://docs.github.com/en/pages/getting-started-with-github-pages/creating-a-github-pages-site

## Ограничения редактора контента

Это редактор существующих HTML-карточек, а не полноценная CMS. Новый товар/услуга в JSON автоматически не создаёт HTML-карточку и отдельный подробный блок. Удаление записи также требует корректировки HTML. Поля полного описания и часть юридических реквизитов пока остаются статическими в страницах. Перед обещанием клиенту полного управления всеми страницами эти связи нужно отдельно доработать. Главная, телефоны, email, график, регион, соцсети и привязанные карточки обновляются через JSON.

## Результаты проверки 24.09.2026

- 5 публичных страниц × 5 ширин (320, 390, 768, 1100, 1440 px): без горизонтального переполнения и битых локальных изображений.
- Внутренние HTML-ссылки и якоря проверены; битых не найдено.
- 8 вкладок админки × 4 ширины (320, 390, 768, 1440 px): без горизонтального переполнения после исправления.
- PHP: неавторизованный доступ, неверный PIN, вход/выход, смена PIN, сохранение контента, валидация, создание/статус/удаление тестовой заявки прошли.
- Демо-форма не делает запрос отправки и не очищает введённые данные.
- Ошибок выполнения JavaScript в проверенных сценариях не обнаружено.
- Реальные Telegram-сообщения не отправлялись. Будущий публичный сервер не проверялся.
